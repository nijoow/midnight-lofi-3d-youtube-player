## 실제 변경과 판단

1. **목록과 재생의 결합 책임**: 페이지는 현재 곡 조회, 자연 종료 후 이동, 수동 선택/이동, 추가/삭제/재정렬과 재생 의도를 한꺼번에 조정했다. 이 응집된 흐름을 `usePlaylistPlayback`으로 이동했다. 저장은 기존 `useRoomState`, IFrame API는 기존 `useYouTubePlayer`가 계속 소유한다. 전역 store나 범용 controller를 추가하지 않았다.
2. **목록 정책 원본**: 추가 가능 여부/불변 추가를 `canAddTrack` / `appendTrack`에 두고 UI 알림, 추가 경계, 복원 제한이 `MAX_PLAYLIST_TRACKS=200`을 공유하게 했다. 같은 이벤트에서 추가 후 선택하는 기존 함수형 상태 업데이트 순서를 유지했다.
3. **검색 경계**: 네트워크 요청/abort/순번·페이지 상태와 JSON 검증·문자 디코딩을 분리했다. `parseSearchResults(unknown)`가 검증된 화면 데이터를 반환한다. 기존 SearchTrack 타입 export도 유지했다. 요청 취소, 최신 응답만 반영, 제출한 검색어와 초안 분리, 페이지 결과 병합은 유지한다.
4. **타이머 경계**: 브라우저 저장 I/O에서 복원 검증을 `restoreTimer`로 옮겼다. 기존 유효 범위·완료 횟수·실제 경과 시간·자동 휴식 시작 금지 계약을 유지하고, 휴식 길이는 `BREAK_SECONDS`를 계산/초기화/표시가 함께 사용한다.
5. **명시적인 견고성 보완**: 검색 응답에 null/primitive/잘못된 ID가 섞이면 그 항목만 제외한다(기존에는 null 속성 접근으로 전체 검색 실패 가능). 정상 결과가 아닌 응답은 빈 성공 화면 대신 복구 가능한 오류로 표시한다. 서버가 제공하는 11자 ID만 받아 URL이 ID로 저장되는 것을 막는다. 정상 API 응답과 정상 사용자 입력 정책은 동일하다.
6. README의 기존 서버 재사용 설명을 실제 Playwright 설정(기본 3122, PORT 지정, 재사용 금지)에 맞췄다.

## 한계와 재현

재생/검색 E2E는 YouTube 대역을 사용한다. 실제 음원 청취·실제 자연 종료·실제 YouTube API 검색·Safari/iPhone/Android 하드웨어는 이번에 검증하지 않았다. 운영은 읽기 메타데이터만 대조했으며 이 로컬 변경은 미배포다. 전체 소스 검토는 모든 상태 조합에 대한 완전한 증명을 뜻하지 않는다.

샌드박스의 최초 git fetch는 DNS 제한, 최초 E2E는 localhost listen EPERM으로 실행되지 않았다. 각각 정식 실행 권한 검토를 거친 재실행이 승인되어 완료됐다. 남은 거절/승인 대기/불확실한 쓰기 결과는 없다. 로컬 테스트 서버는 종료했다.

```sh
# Node 24.22.1, 저장소 루트에서
npm run lint
npm test
npm run build
npm run typecheck
PORT=3192 PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' npm run test:e2e
```

타입 검사, 빌드, 개발/E2E 서버가 동일 .next를 쓰므로 순차 실행한다. 3D/2D 화면 QA는 별도 3193 포트의 생산 빌드를 사용했다.
